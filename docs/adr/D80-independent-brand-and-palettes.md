# D80. 品牌身份、配色与宠物选择相互独立

- **取代**：D77、D78

## 背景

皮肤画的是宿主自己的界面，颜色与字体既可能来自宿主，也可能来自另一个主题插件。使用者要换上自己的标志与强调色，也想要多套只换颜色、不换身份的外观。此前一个插件里装着 Claude 与 DeepSeek 两套主题，品牌档同时决定色板、标志、装饰和宠物，于是换颜色必然换掉标志与角色，移除一套身份时也会连带丢掉只属于它的颜色。宠物包自身已经解决了"原样复用"的问题，却仍按主题各存一份选择。

## 决定

- 品牌身份、配色、字体与聊天框宠物各是一项独立的偏好，互不绑定；同一套标志在每一套配色下都原样保留，切换配色只重写颜色令牌。
- 皮肤不再提供任何第三方品牌的身份：自带的标志、字标、账户彩蛋与专属装饰全部移除，默认身份只有 DeepSeek。读者自定义的名称、标志图、文字标志与着色方式叠在其上，读者提供的那一项优先。
- 配色档只通过令牌生效：一档整套重写宿主别名与皮肤私有令牌，功能样式表一律读令牌，不按品牌分支。每档都要覆盖浅色、深色以及悬停、选中、链接、数据与图表等关联颜色；皮肤自定义的颜色令牌每一档都要有取值或别名，漏掉即构建失败。另有一档跟随宿主：皮肤不写宿主令牌，交给宿主或其他主题插件。
- 配色与字体各自可以选择跟随宿主；强调色只在皮肤自带的配色档下生效，选择跟随宿主时这一项不可操作，读者存下的取值留着。
- 聊天框宠物只有一项选择，不随配色或身份变化。宠物包按原样保存：`pet.json` 与图集的原始字节写进 `~/.petdex/pets/<目录名>/`，内容版本取 `SHA256(清单字节 || 0x00 || 图集字节)`；内容相同的复用目录，内容不同的另存为 `dsh-` 加哈希前缀，既有包永不覆盖。播放器只做适配：给帧表补上动作所在的行、整张图集的行数、逐帧毫秒数与原生动作名，九种动作、行序与逐帧时序都以 Petdex 的图集规范为准，v2 多出的两行保留但不杜撰名称。原有的手绘角色继续保留为手动选择。
- 导入只接受完整宠物包：文件夹、ZIP 与 Petdex 页面三种入口共用同一个校验与落盘路径；ZIP、图集、清单、条目数与像素数各有上限，解压按实际输出字节计数，拒绝穿越路径、重复条目、嵌套目录与非数据文件。链接只解析官方公开目录给出的资源地址，绝不执行页面上的安装脚本。ZIP 与图片分别交给 fflate 与 image-size，不手写解析器。
- 旧的品牌档与按主题各存一份的宠物选择在读取时迁移到新的配色与宠物字段：读者最后保存的新取值优先；迁移只读旧字段，不改写读者的配置文件。

## 后果

- 功能样式表里画面的颜色一律读令牌；写死颜色在跟随宿主时会被别人画的颜色盖住。
- 新增配色档是一条数据改动：在令牌数据源里补齐整套浅色与深色，构建会核对每一档的完备性与宿主别名。
- 强调色的悬停与链接色按固定比例混出，个别颜色上不如手调的调色板准。
- 自定义标志图由宿主半边收下并存进读者自己的目录，升级插件而宿主未重启时这些图缺席。
- 发布包不含宠物原画，首次使用要联网下载；四份预设的地址固定在本仓库，升级它们是一次显式改动。
- 不再提供宠物桌面位置：第三方的桌面程序随宿主启动，运行状态写进全局的 `~/.petdex` 与他人共用一份，它画的形象也不跟随这里的选择，因此整套移除；系统级窗口留给宿主自己的扩展点。
- 导入的包按原清单 id 或哈希目录命名，清单里的 id 不改；两个内容不同但同 id 的包并存，选择时以目录名为准。
- 放弃的做法：按品牌分支写颜色、把自定义品牌做成再添一档品牌，以及让每个功能各自读取当前主题。

## 重审条件

- 宿主提供主题层级或令牌分层机制时，配色与字体改用宿主的层级。
- 宿主提供插件级的文件存储服务时，自定义标志图改存到那里。
- 宿主侧栏的品牌标志与名称插槽成为稳定扩展点时，侧栏的标志与名称改为注册插槽组件。
- 宿主提供原生的置顶窗口扩展点时，宠物桌面位置改为宿主窗口，不再外挂一个可执行文件。
- Petdex 公开一份稳定的按 slug 取包的协议时，链接导入改用该协议而不是目录搜索。
- v2 图集多出的两行有了公开语义时，再把它们接进动作表。
