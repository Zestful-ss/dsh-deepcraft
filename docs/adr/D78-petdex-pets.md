# D78. 复用 Petdex 宠物：原始宠物包与聊天框位置

## 背景

两套主题都需要一个小伙伴：聊天框右上角一只。手绘的角色已经试过，效果与打磨程度都不被接受；Petdex 已经发布了一批带清单、图集和逐帧时序的宠物包，也给出了公开的资源地址。

因此问题不是再画一只宠物，而是让这些原始包在 DSH 的聊天位置出现，同时不重画、不重排、不改字节。

## 决定

- 宠物包按原样保存：`pet.json` 与图集的原始字节写进 `~/.petdex/pets/<目录名>/`，内容版本取 `SHA256(清单字节 || 0x00 || 图集字节)`；内容相同的复用目录，内容不同的另存为 `dsh-` 加哈希前缀，既有包永不覆盖。
- 播放器只做适配：聊天框复用现有的播放器与状态机，给帧表补上动作所在的行、整张图集的行数、逐帧毫秒数与原生动作名；九种动作、行序与逐帧时序都以 Petdex 的图集规范为准，v2 多出的两行保留但不杜撰名称。原有两个手绘角色继续保留为手动选择。
- 一个位置：每个主题各有聊天框宠物一项，出现范围的偏好只在首页与对话之间取舍。
- 导入只接受完整宠物包：文件夹、ZIP 与 Petdex 页面三种入口共用同一个校验与落盘路径；ZIP、图集、清单、条目数与像素数各有上限，解压按实际输出字节计数，拒绝穿越路径、重复条目、嵌套目录与非数据文件。链接只解析官方公开目录给出的资源地址，绝不执行页面上的安装脚本。ZIP 与图片分别交给 fflate 与 image-size，不手写解析器。

## 后果

- 发布包不含宠物原画，首次使用要联网下载；四份预设的地址固定在本仓库，升级它们是一次显式改动。
- 不再提供桌面位置：第三方的桌面程序随宿主启动，运行状态写进全局的 `~/.petdex` 与他人共用一份，它画的形象也不跟随这里的选择，因此整套移除；系统级窗口留给宿主自己的扩展点。
- 导入的包按原清单 id 或哈希目录命名，清单里的 id 不改；两个内容不同但同 id 的包并存，选择时以目录名为准。

## 重审条件

- 宿主提供原生的置顶窗口扩展点时，桌面位置改为宿主窗口，不再外挂一个可执行文件。
- Petdex 公开一份稳定的按 slug 取包的协议时，链接导入改用该协议而不是目录搜索。
- v2 图集多出的两行有了公开语义时，再把它们接进动作表。
