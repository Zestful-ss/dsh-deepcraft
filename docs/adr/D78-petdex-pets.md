# D78. 复用 Petdex 宠物：原始宠物包与两个位置

## 背景

两套主题都需要一个小伙伴：聊天框右上角一只，桌面上另开一个能压在其他窗口上的窗口。手绘的角色已经试过，效果与打磨程度都不被接受；Petdex 已经发布了一批带清单、图集和逐帧时序的宠物包，官方桌面程序也已经在 Windows 上运行，并且自带 DSH 会话事件的桥接。

因此问题不是再画一只宠物，而是让这些原始包在 DSH 里出现两次：一次在网页里，一次在真正的系统级窗口里，同时不重画、不重排、不改字节。桌宠还要在 DSH 最小化后继续显示，并随 DSH 启停；换主题换宠时只能动自己启动的那一只，不能接管或结束使用者自己开的实例。

## 决定

- 宠物包按原样保存：`pet.json` 与图集的原始字节写进官方桌面程序会扫描的 `~/.petdex/pets/<目录名>/`，内容版本取 `SHA256(清单字节 || 0x00 || 图集字节)`；内容相同的复用目录，内容不同的另存为 `dsh-` 加哈希前缀，既有包永不覆盖。
- 播放器只做适配：聊天框复用现有的播放器与状态机，给帧表补上动作所在的行、整张图集的行数、逐帧毫秒数与原生动作名；九种动作、行序与逐帧时序都以官方播放器为准，v2 多出的两行保留但不杜撰名称。原有两个手绘角色继续保留为手动选择。
- 两个位置各自独立：每个主题各有聊天框宠物与桌宠两项，桌宠另有总开关；聊天位置关闭不影响桌宠，出现范围的偏好只约束聊天位置。
- 桌宠复用官方 Windows 程序：首次启用时按固定地址下载，校验长度与 SHA-256 后缓存在插件目录；只通过子进程环境里的 `PETDEX_PET` 选包，不改官方的全局设置文件。官方程序固定监听 `127.0.0.1:7777`，状态写入需要它启动时生成的运行时令牌。
- 所有权先于投递：启动前探测端口；端口已被占用就报告 `external`，既不读取它的令牌，也不发送状态，更不结束它。自己启动时由一个极小的监督进程转交原生子进程，只有 `/whoami` 报出的进程号等于该子进程、健康检查通过且令牌就绪才进入运行状态。
- 生命周期跟随 DSH：宿主进程的一次加载持有一份租约，热重载复用同一个控制器，最后一份租约释放时才停止；监督进程在 IPC 断开时结束自己启动的子进程。换主题或换宠物只重启自己拥有的实例。
- 事件来自宿主半边：DSH 会话事件在 Node 进程中规范化并投递，页面最小化不影响；已接受的状态按根会话留快照，重启后在就绪时回放仍在进行的工作与刚结束不久的结果。未解决的审批压过普通进度，终态与会话销毁会清掉它。
- 导入只接受完整宠物包：文件夹、ZIP 与 Petdex 页面三种入口共用同一个校验与落盘路径；ZIP、图集、清单、条目数与像素数各有上限，解压按实际输出字节计数，拒绝穿越路径、重复条目、嵌套目录与非数据文件。链接只解析官方公开目录给出的资源地址，绝不执行页面上的安装脚本。ZIP 与图片分别交给 fflate 与 image-size，不手写解析器。

## 后果

- 发布包不含宠物原画，首次使用要联网下载；四份预设的地址与官方桌面程序的版本固定在本仓库，升级它们是一次显式改动。
- 桌宠需要 Windows x64 与可以创建窗口的交互会话；其他平台只报告不支持，聊天框宠物照常工作。
- 官方程序固定单实例与固定端口：使用者自己开着一只时，DSH 只能提示先关闭它，不能同时提供系统级桌宠。
- 换主题时桌宠会短暂消失再出现；位置、缩放与拖拽都由官方程序管理，本插件不提供这些设置。
- 同一个根会话只回放一份最新状态：快速连续切换主题时，中途的状态不会逐一重放。
- 导入的包按原清单 id 或哈希目录命名，清单里的 id 不改；两个内容不同但同 id 的包并存，选择时以目录名为准。

## 重审条件

- 官方播放器提供选宠或热切接口时，换宠不再重启进程。
- 官方播放器把固定端口或单实例改成可配置时，外部实例与 DSH 托管实例可以并存。
- 宿主提供原生的置顶窗口扩展点时，桌宠改为宿主窗口，不再外挂一个可执行文件。
- Petdex 公开一份稳定的按 slug 取包的协议时，链接导入改用该协议而不是目录搜索。
- v2 图集多出的两行有了公开语义时，再把它们接进动作表。
