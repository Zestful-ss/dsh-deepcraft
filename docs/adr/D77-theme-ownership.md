# D77. 品牌与主题归属

- **取代**：D30、D50、D64

## 背景

皮肤画的是宿主自己的界面，颜色与字体既可能来自宿主，也可能来自另一个主题插件。品牌要在保留宿主品牌与换成皮肤自带品牌之间切换，而使用者还想换上自己的标志与强调色。这些都只换画出来的样子，不改功能的行为；把它们写成功能里的分支，每张样式表都要知道当前是哪个品牌。

同一个插件现在容纳 Claude 与 DeepSeek 两套主题，某些装饰只属于其中一套，例如复刻 Claude 账户暂停页的彩蛋。把这种归属写进每个功能自己的判断，会让同一件事在账户入口、设置页和功能安装处各写一遍，主题一换就漏掉一处。

## 决定

- 配色与字体各是一项偏好，可以选择跟随宿主；跟随宿主时，皮肤的画面读宿主令牌的别名，结果不取决于样式表的加载先后。
- 品牌按档切换，档只决定色板、标志与主题专属装饰，不改共同功能的行为；品牌偏好每加一档，功能样式表不动。
- 配色切换只靠令牌：一档整套重写宿主别名与皮肤私有令牌，功能样式表一律读令牌。
- 皮肤自己定义的颜色令牌，每一档都要有对应的取值或别名，漏掉即构建失败。
- 自定义品牌是叠在所选品牌之上的一层：名称、标志图、文字标志、着色方式与强调色各自独立，读者没提供的那一项保持所选品牌原样。
- 共同功能不带品牌分歧；仅属于某些主题的装饰功能由功能清单声明所属品牌，运行时按当前品牌统一安装或拆除，功能模块不再各自判断。
- 强调色只在皮肤自带的配色档下生效；选择跟随宿主时这一项不可操作，读者存下的取值留着。

## 后果

- 皮肤自带的私有令牌每加一条，都要在跟随宿主的一档里补上别名，并进每一档品牌的色板。
- 功能样式表里画面的颜色一律读令牌；写死颜色在跟随宿主时会被别人画的颜色盖住。
- 强调色的悬停与链接色按固定比例混出，个别颜色上不如手调的调色板准。
- 自定义标志图由宿主半边收下并存进读者自己的目录，升级插件而宿主未重启时这些图缺席。
- 主题专属功能的设置行在别的主题下保持禁用并写明原因，读者存下的取值不改。
- 放弃的做法：为每个品牌写一套按品牌分支的规则，把自定义品牌做成再添一档品牌，以及让每个功能各自读取当前主题。

## 重审条件

- 宿主提供主题层级或令牌分层机制时，配色与字体改用宿主的层级。
- 宿主提供插件级的文件存储服务时，自定义标志图改存到那里。
- 宿主侧栏的品牌标志与名称插槽成为稳定扩展点时，侧栏的标志与名称改为注册插槽组件。
- 主题专属功能需要跨插件共享或由皮肤中心统一编排时，归属改由宿主的扩展点声明。
