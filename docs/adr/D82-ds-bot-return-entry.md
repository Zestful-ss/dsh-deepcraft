# D82. Bot 面保留一个返回主题的入口

## 背景

ds-bot 的整页 Bot 外壳与宿主页面之间只有单向的快捷入口：Agent 模式下它往宿主的侧栏页脚注入一个鲸鱼按钮，一下进 Bot 面；Bot 面没有对称的按钮，回宿主只有「账号菜单 → Settings → Mode → Classic Agent mode → Switch」这一条路，读者要在一个设置对话框里找两跳。读者要求在主题插件这边补上回程。D81 的整页让位条因此开一个窄口；这一条说明例外的范围、控件放在哪里，以及按下之后怎么切回去。

## 决定

- 让路仍然整页进行：不挂本主题的样式表、不写本主题的 body 标记、不运行其他功能。唯一保留的是这一个返回入口，它是让路期间本包留在页面上的全部界面。
- 入口画在 ds-bot 自己的 Bot 侧栏页脚里，是账号按钮所在行的第一个子节点，紧挨账号按钮左侧；使用 ds-bot 的 `--bt-*` 令牌取色与字体，外观与它自己的按钮同族。只在这个 Bot 面占着页面时出现；Agent 模式、另一个皮肤接管或 ds-bot 不在页面上时不出现。新版 ds-bot 已不再渲染宿主的 `sidebar.footer.action` 槽位，因此入口直接落在账号行上，而不是只登记一个看不见的槽位。
- 文字取读者自己的品牌名，没有品牌名时用 DeepCraft；带一个回退箭头。宽度按页脚剩余的横向空间收缩，账号头像始终留出位置。
- 按下时走 ds-bot 自己的切换路径：账号菜单里的「经典 Agent 模式」项，或它设置页“模式”一行里的 Switch。两项都在时优先菜单项；只有这个版本找不到任何一项时，才写入 ds-bot 自己保存模式的 `ds-bot:surface` 为 `agent` 并重新载入页面。不读 ds-bot 的 React 状态，也不改写它的其他存储。
- 常用路径不重新载入，页面由 ds-bot 自己的模式状态切换；只有找不到它的入口时才会退回一次重载，那一次会丢 Bot 面尚未发送的草稿。ds-bot 公开模式的读写接口后，连这条兜底也改用接口。

## 后果

- 回程从四步变成一次按下；正常路径走 ds-bot 自己的切换，不重新载入页面，找不到它的控件时退回一次重载。Agent 侧正在进行的会话不受影响，宿主会话仍在。
- 让路不再是纯粹的「零界面」：Bot 面上多一个主题自己的按钮，它必须永远不依赖主题样式表或主题令牌，否则让路就不彻底。
- 依赖 ds-bot 的保存键与它侧栏页脚账号行的结构；两者变化时，入口的位置或回程都会失灵，由端到端 `dsBot` 场景在真实宿主上守住。入口插在 ds-bot 的 React 树里，它重画这一行时可能被移除，所以旁边有一个只观察该行的恢复器，把按钮放回去。
- 入口在 ds-bot 的设置对话框之下，被它的遮罩盖住；读者打开设置时不会误触。

## 重审条件

- ds-bot 公开页面模式或返回入口的接口时，改为调用接口并删除菜单与设置对话框的点击路径以及保存键兜底。
- ds-bot 自己补上 Bot 面的反向入口时，删除这个按钮，让路回到 D81 的零界面。
